# SAFEGUARD — локальный DNS-блокировщик для Android

Фоновое приложение без интерфейса. Блокирует домены из одного TXT-файла. Без аккаунтов, серверов, облака, рекламы и аналитики.

> ## Статус проверки — читать первым

> Поэтому код **ни разу не компилировался**, тесты **не запускались**, APK **не собран**.

> перезагрузка) не проверялась вообще.

## Как это работает

* `VpnService` поднимает TUN, в который маршрутизируются **только** адреса DNS: фиктивные `198.18.0.2` / `fd00:5afe:6a4d::2`
  и популярные публичные резолверы (8.8.8.8, 1.1.1.1, 9.9.9.9 и т. д. — чтобы приложения с «зашитым» DNS не обходили фильтр).
  Остальной трафик в туннель не попадает, HTTPS не перехватывается, содержимое трафика не читается.
* Запрос из TUN разбирается (UDP и TCP, IPv4 и IPv6). Домен из blocklist (или его поддомен) получает `NXDOMAIN`,
  остальные запросы пересылаются DNS-серверам сети, которая сейчас используется (сокеты защищены `protect()` и привязаны к сети — петель нет).
  Если сеть не сообщила DNS-серверов, используются 1.1.1.1 и 8.8.8.8.
* Нет сети или upstream не ответил за ~2,5 с — клиент получает `SERVFAIL`. Битый DNS-пакет — `FORMERR` или игнорируется.
* Ответы UDP больше 1452 байт заменяются усечённым (бит TC), клиент повторяет запрос по TCP.

Структура: `service` (VpnService, TUN-цикл, уведомления), `dns` (разбор DNS, фильтр, IP/UDP/TCP-пакеты),
`rules` (разбор и проверка доменов), `storage` (SAF, настройки, кэш правил), `network` (upstream, сеть, `protect`), `boot`.

## Файл blocklist.txt

Рекомендуемое расположение: `Внутренняя память/SAFEGUARD/blocklist.txt`.

```text
# SAFEGUARD BLOCKLIST
example.com
casino-example.net
```

* Один домен в строке; `#` — комментарий (в том числе после домена); пустые строки и дубликаты игнорируются.
* Блокируется сам домен и все поддомены. `notexample.com` и `example.com.evil.org` не затрагиваются.
* Регистр не важен, завершающая точка и префиксы `*.` / `.` допускаются. IDN (`пример.рф`) переводится в punycode.
* Не принимаются: URL, пути, порты, IP-адреса, имена из одной метки (`com`) — такие строки пропускаются.
* Пустой файл (или только комментарии) — блокировок нет.
* Кодировка — UTF-8 (BOM допускается). UTF-16, бинарные данные и файл, где нет ни одного валидного домена, считаются повреждёнными.

## Сборка

Нужны JDK 17+ и Android SDK (platform 35). Android Studio сама создаст wrapper и `local.properties`.

```bash
gradle wrapper --gradle-version 8.9   # один раз; jar-файл wrapper в архив не входит
./gradlew test                        # unit- и loopback-тесты на JVM
./gradlew assembleDebug               # app/build/outputs/apk/debug/app-debug.apk
```

Debug-APK подписан отладочным ключом и ставится сразу: `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
Для release добавьте свою подпись в `app/build.gradle.kts`. Если версии плагинов не подойдут вашей среде,
поднимите AGP / Kotlin / Gradle до актуальных совместимых.

## Установка и первоначальная настройка

1. Установите APK и откройте SAFEGUARD (иконка — только для настройки, экрана нет).
2. Разрешите уведомления (нужно для системного уведомления VPN; без разрешения защита тоже работает).
3. Откроется выбор папки: создайте/выберите папку `SAFEGUARD` во внутренней памяти → «Использовать эту папку» → «Разрешить».
   Доступ сохраняется навсегда. Если `blocklist.txt` там нет, он создаётся. Корень памяти и `Download` Android выбрать не даёт.
4. Подтвердите системный запрос VPN. Защита запустится, приложение закроется; в шторке будет уведомление.

Повторное открытие приложения заново включает защиту, если она была остановлена.

## Редактирование списка

Измените `blocklist.txt` любым редактором и сохраните. Новые правила применяются сами, без перезапуска VPN:
по уведомлению от провайдера файлов (если он их шлёт) и по резервной проверке содержимого каждые ~5 секунд.
Чтобы не поймать файл «на середине записи», новое содержимое применяется, только если оно одинаково при двух чтениях подряд (пауза 0,4 с).
Замена файла новым документом с тем же именем учитывается, так как файл ищется по имени при каждом чтении.

Если файл исчез, не читается или повреждён, остаются **последние рабочие правила**; причина показана в уведомлении.
Последняя рабочая копия хранится и в приватной памяти приложения, поэтому правила действуют и после перезапуска процесса/телефона,
пока внутренняя память недоступна.

## Always-on VPN и перезагрузка

Настройки → Сеть и интернет → VPN → SAFEGUARD → шестерёнка → «Постоянная VPN» (Always-on VPN).
Блокировку без VPN («Lockdown») включать не нужно и по умолчанию она выключена; не включайте, пока не убедитесь, что всё работает.
После перезагрузки защиту поднимает система (Always-on) либо `BootReceiver`, если пользователь её включал и разрешение VPN сохранилось.
Если разрешение потеряно (другое VPN-приложение, «Отключить» в настройках), SAFEGUARD останавливается и показывает уведомление.
Служба перезапускается системой после остановки процесса (`START_STICKY`).
Остановить защиту: Настройки → VPN → SAFEGUARD → «Отключить».

## Устранение ошибок

| Симптом | Что делать |
|---|---|
| В уведомлении «blocklist.txt не найден / не читается» | Откройте приложение и заново выберите папку; проверьте, что файл называется ровно `blocklist.txt`. |
| «blocklist.txt повреждён» | Сохраните файл как UTF-8 без лишнего мусора; хотя бы одна строка должна быть корректным доменом. |
| Правила не меняются | Подождите ~5–6 с. Проверьте уведомление; убедитесь, что правите файл именно в выбранной папке. |
| Нет интернета при включённой защите | Отключите VPN в настройках и откройте issue с моделью устройства; проверьте режим Private DNS (см. ограничения). |
| Защита пропала после перезагрузки | Включите Always-on VPN; на Xiaomi/Honor/Samsung разрешите автозапуск и отключите ограничение батареи для SAFEGUARD. |
| Другое VPN вытеснило SAFEGUARD | В Android одновременно активно одно VPN. Используйте одно из двух. |

## Известные ограничения

* **Private DNS в строгом режиме** (указано имя хоста) и приложения с собственным DNS-over-HTTPS/TLS (например, Chrome «Безопасный DNS»,
  Firefox DoH) могут обходить фильтр. Для 16 популярных публичных резолверов DoT/DoH блокируется сбросом соединения, чтобы
  приложение откатилось на системный DNS, но произвольные DoH-серверы по своим адресам перехватить без разбора HTTPS нельзя.
  Чтобы фильтр работал, поставьте Private DNS в «Выкл.» или «Автоматически», а в браузерах отключите собственный DoH.
  Строгий Private DNS приложение обнаруживает и показывает предупреждение в уведомлении.
* Блокируются только DNS-имена. Обращение к сайту по IP-адресу или из кэша DNS приложения/ОС фильтр не остановит.
* Ответ на заблокированное имя — `NXDOMAIN` для любых типов записей (с кратким отрицательным TTL 30 с).
* IPv6-пакеты с расширенными заголовками и фрагментированные пакеты игнорируются (для DNS на практике не встречаются).
* Собственный TCP-стек минимальный: один DNS-запрос за другим по соединению, без повторных передач (канал TUN локальный и без потерь).
* Список ограничен 16 МБ. Подзапись в файл блокировки приложение не ведёт (только создаёт пустой файл при первой настройке).
* Одновременно активно одно VPN; Always-on и Lockdown управляются системой.
* Батарея: таймер раз в 5 с читает небольшой файл; DNS-пересылка работает только при реальных запросах.
* Устройства Samsung/Pixel/Xiaomi/Honor: поведение SAF-провайдера и энергосбережения может отличаться; на практике не проверялось.
